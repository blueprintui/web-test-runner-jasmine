## Project Overview

web-test-runner-jasmine is a plugin that integrates Jasmine testing framework with Web Test Runner for browser-based test execution. It translates Jasmine test events into Web Test Runner's session format.

## Commands

```bash
pnpm run ci          # Full pipeline: clean → build → test
pnpm run build       # TypeScript compile + esbuild bundle
pnpm run test        # Run tests with coverage
pnpm run clean       # Remove dist/
pnpm run setup       # Install deps + Playwright browsers
```

## Architecture

### Build Pipeline
1. TypeScript compiles `src/*.ts` (excluding specs) to `dist/`
2. esbuild bundles `dist/jasmine/index.js` → `dist/jasmine/index.js` (bundles jasmine-core, keeps @web/test-runner-core external)
3. `package.json` and `README.md` copied to `dist/` for npm publishing

### Key Files

- **src/index.ts**: Exports `jasmineTestRunnerConfig()` - configures Web Test Runner with custom HTML harness that inlines the bundled framework
- **src/jasmine/index.ts**: Single-file browser framework containing:
  - Jasmine initialization
  - Custom reporter that builds test tree structure (`SuiteNode`, `SpecNode`)
  - Console reporter for debug mode
  - Tree traversal helpers (`findParentNode`, `findResultNode`)
  - Inline ANSI color codes and assertion (no external dependencies)
- **src/jasmine/types.d.ts**: Type augmentation for Jasmine's `parentSuiteId`

### Data Flow
1. Web Test Runner loads HTML harness (generated by `jasmineTestRunnerConfig()`)
2. Bundled framework (`index.mjs`) is inlined into HTML and executes in browser
3. Custom Jasmine reporter builds hierarchical test results
4. Results sent to Web Test Runner via `sessionFinished()`

### Browser vs Node
- `src/index.ts` runs in Node (Web Test Runner plugin)
- `src/jasmine/index.ts` runs in browser (bundled with esbuild)

### Why esbuild bundling?
The framework code is inlined into HTML via `fs.readFileSync()`. Inline scripts can't resolve bare import specifiers, so `jasmine-core` must be bundled. `@web/test-runner-core` is kept external as it's designed to work in the test runner's browser context.
